# v0.5.0：Mac 性能优化与复核

按“单通道／内存 → Accelerate → GCD → 受控多页 → Metal”的顺序实施与评估。前四项进入正式处理链，Metal保留为独立实验基准。常见灰度书页的处理已经进入 Gray8 流水线，保留现有采样核、每步取整和用户操作顺序。彩色及不支持的操作保留 RGBA 回退。

## 实际书页：55 次同机前后对照

使用用户提供的第 150–160 页，共 11 张灰度 JPEG，1672×2656／2658。宽高各放大两倍，输出约 1777 万像素。参数：双三次 → 亮度104／对比度110／Gamma110 → 高斯半径1、强度30% → USM半径2、强度60%、阈值2 → Sauvola半径20、k=0.2 → 去毛边补凹槽1遍。

## 实现

### 1. 连续单通道与工作区

- 灰度源先进行一次现有sRGB规范化，再提取单通道，避免直接跳过颜色管理造成变化。
- 常用缩放、裁切、旋转、色调、高斯／Box、USM／Laplacian、减值、二值化、去斑、去毛刺、镜像和反色可使用单通道实现。自动内容框及部分复杂滤镜会走RGBA回退，并在可证明仍为灰度时恢复Gray8。
- 1777万像素一张位图约由71.1MB降至17.8MB，同尺寸临时空间也缩小。每页复用两块卷积／阈值临时空间，预览及批处理还跨相邻任务复用工作区；任务结束后限制可保留的临时缓冲区总量为64MiB。
- 无变化的输入映射直接复制或查LUT；高斯混合、USM使用65536项字节对查表，保留原浮点公式的取整。测试穷举多组强度／阈值的全部字节对。
- 严格二值PNG／TIFF直接输出1-bit；4／16级使用2／4-bit；普通灰度直接8-bit。打包在C++中按行并行，导出无需先生成RGBA显示图。

### 2. Accelerate／vImage

Mac默认使用vImage处理Gray8高斯的横、纵两遍；边界延伸、整数核和每遍取整与现有算法一致。vImage单块禁止再次自行分线程，由外部共享线程预算调度。调用不支持某个尺寸时回退便携整数实现。Linux保持便携C++。

核心测试同时强制检查便携与vImage路径，在小图、所有半径、旋转、不同线程数、Sauvola与抖动组合下与RGBA参考比较。

### 3. GCD动态分块

Mac通过`dispatch_apply_f`复用系统工作线程，从多个较小行块中动态领取工作；默认最多8个活动计算任务。由系统调度性能核和能效核，不固定绑定某类核心。预览使用userInitiated队列；设置批处理预算时使用utility队列。异常在工作块中收集，全部完成后由C边界返回错误。

Linux保留标准线程实现，也使用动态领取行块。大图的默认上限仍保守地设为8，高核心数Mac的最佳上限尚需更多硬件验证。

### 4. 受控页间处理

`BatchExporter`最多同时处理两页，并将页内线程数纳入总CPU预算。少于4个可用CPU、预计工作集过大或复杂旧版排版栈自动串行；内存预算取物理内存五分之一、最高1.5GB，工作集估算保留RGBA回退余量。

文件名在并行开始前统一检查，按大小写与Unicode规范化后的键预留，避免Mac默认文件系统中的内部覆盖竞争；结果／日志按原页序保存。取消在步骤之间检查，进度保持单调。测试覆盖两页并发、重复与大小写冲突、低内存预算、取消和源文件保留。

CI还用4张约1777万像素合成页，分别比较单页和双页模式，记录runner实际CPU／内存及自动选择。云runner核数较少时自动串行是预期行为；不能用强制双页的结果推断高核心数真机表现。

### 5. Metal评估结果：保留独立基准，正式版使用CPU

`tests/MetalCandidate.swift`和`scripts/benchmark-acceleration.sh`保留高斯＋USM候选的GPU评测。采用相同整数二项式核和每遍取整，混合读取CPU生成的65536种字节对LUT；计时包含上传、分配、结果复制。候选基准与CPU像素对照一致。

CPU查表和vImage优化完成后，这次两个runner的GPU候选没有稳定胜过CPU。更重要的是，将自动校准接入完整批量流程时，在ARM优化构建中稳定触发了对象释放崩溃；单页与AddressSanitizer构建通过不能代替这个失败的正常批量检查。调试栈定位到校准路径，原型调整后仍未达到发布要求。

因此，**正式应用移除了自动校准及GPU调用，采用Gray8＋vImage CPU路径**。Metal候选只用于独立测试，不在应用的编译输入和链接依赖中。批量压力测试继续作为发布门槛，而非忽略失败。未来需要单独解决校准路径的稳定性和实际收益，再考虑将更多操作驻留GPU。

## 完成后的审核

已进一步修正：C接口异常边界、灰度快路径作用范围、重复工作区初始化、跨任务临时空间保留上限、大小写文件名并发冲突。GPU自动校准未通过正式批量检查，已移出发布应用。多页压力测试还促使补充了Swift借用底层指针时对CFData、工作区及GPU缓冲区的显式生命周期保护，原生ARM测试加入Swift／C联合AddressSanitizer复核。Linux运行ASan／UBSan，两种Mac架构执行核心、原生功能、CPU／GPU候选、完整流水线和批处理检查；最终通用包验证架构与签名。

仍有改进空间，按本次数据排序：

1. **Sauvola、去毛刺与缩放的SIMD和缓存访问。** 实际书页的CPU路径中，这些已与高斯／USM同属主要耗时，而不再由单一热点占绝大多数。
2. **复杂灰度操作的回退。** 中值／双边、自动内容框等还有RGBA转换或三通道开销，后续可扩展专用Gray8实现。
3. **颜色输入与显示。** 为保持颜色管理，灰度源初次规范化仍借助RGBA；RGB编码但像素恰为灰度的源图暂未全图自动检测，可通过显式灰度步骤进入后续Gray8路径。预览最后仍需显示位图。更直接的色彩等价转换需单独验证。
4. **GPU稳定性、驻留与校准。** 正式版未启用GPU。候选仍有上传、结果复制和同步成本；后续需先独立解决自动校准的ARM稳定性，再比较更多连续操作驻留GPU的收益。
5. **高核心数硬件。** 超过8核的Mac、不同P／E核心比例、真实GPU和长期批量任务仍需真机调优。页间并行可能受内存带宽、PDF解析锁和编码限制，不应无上限增加线程或同时页数。

未把原有滤镜替换成近似算法。附带图片的对照也不等同于已定位此前原始PDF导入的内容缩小反馈；还需要原始问题PDF与操作栈复现该路径。
