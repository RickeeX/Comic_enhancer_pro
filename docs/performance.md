# 大图处理审查与优化（v0.4.2）

审查覆盖 C++ 像素核心、Swift/CoreGraphics 位图交接、PDF 导入、顺序操作栈、预览任务和导出。目标是保持操作顺序、滤镜定义及输出质量，同时减少 3000 万像素页面的重复工作。

## 已处理的瓶颈

| 路径 | 先前实现 | 当前实现 |
| --- | --- | --- |
| 普通像素操作 | 无缩放也做浮点坐标映射、四点插值和边界夹取 | 整数采样快路径，直接 LUT／灰度转换；裁切和整 90° 旋转也适用 |
| 高斯模糊 | 两遍浮点卷积，每个采样点重复检查边界 | 固定半径整数二项式核，填充行边界、复用纵向行指针；每遍仍按原定义取整 |
| 方框模糊 | 每个像素累加整个一维窗口 | 横、纵滑动和，复杂度 O(像素数)，不随半径增长 |
| 中值滤波 | 每个像素每通道重新收集、选择排序 | 5×5／7×7 使用两级滑动直方图；3×3 保留小窗口选择 |
| 双边滤波 | 邻域重复求亮度，和中值分支混合 | 亮度预计算、专用内核，空间／灰度权重查表 |
| USM | 先复制整张原图，再分配两张模糊缓冲区 | 模糊只读原图，直接与结果混合；Laplacian 仍保留必要快照 |
| 固定／Otsu 二值化 | 额外灰度数组及多遍复制 | 无旧式形态清理时直接在输出缓冲区二值化 |
| 双三次排版／缩放 | 每输出像素 4×4 二维计算 | 可分离计算，工作线程缓存 4 条浮点行，放大时复用；不分配全图浮点中间图 |
| 自动内容框（不忽略斑点） | 遍历全部连通域 | 并行扫描边界；需要忽略小斑点时才使用连通域 |
| 二值去毛刺 | 逐像素重复旋转匹配模板 | 等价邻域掩码，平坦区域提前跳过 |
| Swift／C++ 位图交接 | 每步 CoreGraphics 重绘、Array→Data 整图复制、清零输出 | 合格的紧密排列 sRGB 数据直接借用；核心输出分配由 CFData 接管，缩放也直接写输出 |
| 过期预览 | 当前完整操作栈算完才丢弃 | 操作步骤之间检查取消，跳过剩余步骤 |

所有 C++ 代码保持可移植，不要求 AVX2、特定 M 系列指令或 `-march=native`。通用应用分别用 `-O3` 编译 x86_64、arm64 核心，Swift 使用 `-O -whole-module-optimization`。并行默认最多 8 个线程，避免整批页面同时过度并发而耗尽内存。

## 正确性与边界

- 独立参考卷积和排序检查高斯、方框、中值，覆盖小图、所有半径和并行分块边界；滤镜结果保持逐字节一致。
- 双线性／双三次与直接二维参考比较，分离后的浮点求和顺序可能带来最多 1/255 的通道差异；保留原核与采样位置。
- 穷举 512 种 3×3 二值邻域，检查 3 遍去毛刺、补缺口开关与原模板一致。
- 不直接借用带自定义 Decode、透明通道、特殊色彩空间或裁切偏移的 provider；这些仍由 CoreGraphics 归一。测试覆盖裁切 provider 和颜色一致性。
- 原生回归覆盖内嵌 JPEG 的 300→400 DPI、自动／显式源 DPI、缩略／全尺寸／导出内容占比。此测试是特定可控样本，不代表已定位用户原始 PDF 中的异常；尚需原始问题页面及操作栈才能确认。
- Linux 执行 AddressSanitizer／UndefinedBehaviorSanitizer；Intel 和 Apple Silicon 执行原生集成、性能及 Universal 构建检查。

## 仍然较贵的工作

双边滤波保持精确二维邻域，复杂度仍为 O(像素数×半径²)；没有用近似算法悄悄替换。Floyd–Steinberg 抖动有误差传播依赖，保持串行扫描以保留输出。需要忽略小斑点的内容框、去斑、连边清除仍执行连通域遍历。PDF 图像解压、色彩转换及 PNG／TIFF 编码由系统编解码器处理，压缩率和文档结构影响很大。

核心暂用 RGBA8，一张 3000 万像素位图约 120 MB；大图滤镜仍需要工作缓冲区。后续可继续评估单通道流水线、专用 SIMD 和可选近似双边算法，但应分别验证画质与内存收益。当前不使用跨步骤融合，因为用户可自由重复、排序操作，每步的取整和二值化语义需要保留。
